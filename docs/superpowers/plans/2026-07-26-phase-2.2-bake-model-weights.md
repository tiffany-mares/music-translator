# Phase 2.2 — Bake Model Weights into the Container Image — Implementation Plan

## Context

Phase 2.1's container downloads ~3–4 GB of model weights (Whisper large-v3 ~3 GB via Hugging Face, Demucs htdemucs ~80 MB via torch hub) at every job start. Phase 2.2 (architecture.md §10, line 467) bakes both into image layers at build time so a job's start-to-first-inference time drops. §5.3's Dockerfile sketch shows the two `RUN python -c "..."` layers; the doc specifically calls out that an earlier version missed the Demucs one.

**Done-when (§10, verbatim):** "job start-to-first-inference time visibly drops versus 2.1's cold run."

**Hard sequencing constraint:** 2.1's cold-run SageMaker job — the baseline this phase is measured against — has not run yet (blocked on the pending ml.g4dn.xlarge quota case `341e4965`, monitor `bse8000u8` is watching). Everything in Part A below is local/ECR work safe to do now under a new `:2.2` tag; **Part B must wait** until 2.1's job has completed and its baseline is recorded in `notes/phase2.md` (2.1 plan Tasks 6–8). The already-pushed ECR `:2.1` image is the baseline artifact — never rebuild or overwrite that tag.

**Facts established by exploration:**
- `faster_whisper` 1.0.3 exports `download_model('large-v3')` (package-level, `faster_whisper/utils.py:47`) — downloads the CT2 model into the HF cache (`/root/.cache/huggingface/hub/models--Systran--faster-whisper-large-v3`) *without* loading it. §5.3's verbatim `WhisperModel('large-v3', device='cpu')` would load ~3 GB+ into the ~7.5 GB Docker VM during build — use `download_model` instead and record the deviation.
- `demucs.pretrained.get_model('htdemucs')` (§5.3 verbatim) downloads to `/root/.cache/torch/hub/checkpoints/955717e8-8726e21a.th` and loads the ~300 MB bag — safe at build time, doubles as a load check.
- Basic Pitch needs no baking: weights ship in the wheel (`basic_pitch/saved_models/icassp_2022/nmp`) — this answers §5.3's "Confirm Basic Pitch's bundled model doesn't need the same treatment."
- Container runs as root on SageMaker, so build-time `/root/.cache` is the same cache the runtime reads. `stages/transcribe.py:28` instantiates `WhisperModel(model_size, ...)` with default cache resolution — it will hit the baked HF cache.
- Phase 2.1 evidence of the cost being eliminated: the first local smoke run downloaded both models (seen in task logs); SageMaker cold baseline numbers will be in `notes/phase2.md` once 2.1's job runs.

## Part A — image work (safe now, while quota is pending)

### Task A1: Branch + Dockerfile bake layers

- [ ] `git checkout -b phase-2.2-bake-weights` (from `phase-2.1-containerize` HEAD)
- [ ] In `container/Dockerfile`, after the two existing `RUN python -c` verification layers and **before** the `COPY ml_stages.py ...` block (so code edits never invalidate the 3 GB weight layers), add:

```dockerfile
# Phase 2.2: bake model weights into image layers - no download on job start.
# Both Demucs AND Whisper (section 5.3 notes an earlier doc version missed Demucs).
# Basic Pitch ships its weights inside the wheel (basic_pitch/saved_models) - confirmed, no baking needed.
RUN python -c "from demucs.pretrained import get_model; get_model('htdemucs')"
# download_model instead of section 5.3's WhisperModel('large-v3', device='cpu'):
# instantiating would load the ~3 GB model into RAM at build time; only the
# cached download is needed. Same files, same HF cache location.
RUN python -c "from faster_whisper import download_model; download_model('large-v3')"
# Fail the build loudly if the caches didn't land where the runtime will look.
RUN python -c "import pathlib; d=pathlib.Path('/root/.cache/torch/hub/checkpoints'); w=pathlib.Path('/root/.cache/huggingface/hub'); assert any(d.glob('*.th')), 'demucs checkpoint missing'; assert any(w.glob('models--Systran--faster-whisper-large-v3/**/model.bin')), 'whisper model missing'; print('baked weights OK')"
```
